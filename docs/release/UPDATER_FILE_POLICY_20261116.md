# 更新器：文档与运行文件的校验分离

日期：2026-11-16。状态：源码与临时冻结助手验证完成，未提交、推送或打正式发行包。
本方案取代 [Issue #14 第一轮](ISSUE_14_UPDATE_DOCUMENTS_20261116.md) 的“五个文档、仅本次不变时例外”方案。

## 以前修了什么，为什么仍然出错

Git 历史中 `4a2619a`（2026-09-20，v2.3.1）只增加了对旧用户替换
`_internal/nvngx_dlssnr.dll` 的兼容：该 DLL 在本次发行不变时允许保留自定义版本。
没有将说明文档从运行基线分离；后续提交也没有补齐这条策略。
第一轮仅为少数未变化 README 增加例外，目标一旦改文档仍会失败，因此不能作为最终修复。

## 现在的规则

| 对象 | 本地安装前后强制一致性校验 | 更新行为 |
| --- | --- | --- |
| README、更新日志、使用说明、许可证、第三方声明、附加包说明 | 不校验其与官方安装清单是否一致 | 原样官方文档可随版本更新/备份/移除；本地删改、不可读或新路径已有自用文档时保留 |
| 主程序、助手、DLL/PYD、Python 代码、依赖与运行资源 | 严格校验 | 修改/缺失时停止，避免混装 |
| 模型权重、运行配置、组件协议与依赖元数据 | 严格校验 | 不因它们是 JSON/TXT 或位于许可证目录就跳过 |
| 用户设置、队列、输出、自用 mods DLL/模型等清单外文件 | 不作官方基线校验 | 保留；运行文件新增路径发生冲突时仍拒绝覆盖 |
| 正式发行基线、归档、下载摘要、manifest、全部 payload | 继续全部校验 | 与本地文档策略分开；不能减弱发布来源和下载完整性验证 |

路径、符号链接、重解析点和硬链接检查保留，文档路径被目录/链接占用不属于可忽略的字节差异。
既有自定义内置 DLL 例外保留原有边界。

分类以受管文件的文档类型、明确文档命名和许可文本用途为依据。
不忽略整个 `_internal`/mods/licenses，也不将所有 TXT/JSON 当作文档。
例如 `entry_points.txt`、`top_level.txt`、`enhancement.json`、运行库 `manifest.json`、
`README.dll`、`AUTHORS.py`、`LICENSE.pth` 都继续按运行文件处理。

按正式 v3.1.4 清单只读统计：

| 形态 | 总文件 | 从本地强制一致性校验中分离的文档 | 仍校验的运行文件/资源 |
| --- | ---: | ---: | ---: |
| lite | 1,882 | 199 | 1,683 |
| full | 4,296 | 275 | 4,021 |

完整路径分类和机器验证记录见 [file-policy-evidence.json](issue14-20261116/file-policy-evidence.json)。

## 实现及防回归

- 主程序和助手共用 `delta_update.py`：安装前跳过本地文档字节校验；安装后也不因文档不匹配而回滚。
- `installation_changes` 独立决定是否同步某份文档。仅在此时读取本地文档以保护用户修改，
  差异或读取失败都只保留该文档，不触发升级失败。未变化文档不读取其哈希。
- 目标文档即使有修改、移除或新增，也不要求用户先恢复官方旧 README。
  文档备份前发生编辑、无法读取或只读/被占用导致写入失败时，运行文件更新继续；路径安全错误仍拒绝。
- 已参与事务的原样官方文档使用既有备份和 journal 恢复。回滚时保留事务期间新增的用户笔记。
  payload 仍逐项验证，即使某份文档将被保留，也不能借此跳过暂存文件被篡改的检查。
- `verify_release_upgrade.py` 同步区分运行完整性和文档，避免验收工具自己再次拿 README 阻断正确升级。
- 冻结助手构建门禁同步升级：目标实际改动多类文档，再分别测试 lite 缺文档、full 改文档，
  同时检查设置、内置自定义 DLL、mods DLL 和备份。`-SkipTests` 无法跳过。

## 验证

1. 更新器、助手、发布工作流、真实升级验收脚本、打包契约和 GUI 更新契约主组：105 项、60 子测试通过。
2. 补充文档读写失败、选择后编辑、异常退出恢复和发行验收工具本地文档场景后，
   对应两个模块定向复验：53 项、58 子测试通过（与主组有重叠）。
3. 正式发行基线的 README 被修改时，打包预检仍拒绝：新增专项 1 项通过。
4. 新冻结助手：lite 缺文档、full 改文档、lite 原样官方文档随版更新三次真实合成事务均退出 0、complete。
   第三次探针使用 `-O`，门禁不依赖 Python assert。
5. 未跑全量回归，未复制正式运行环境；冻结验证限合成小文件，不等于完整发行包/GPU/干净机器验收。

已发布 v3.1.3/v3.1.4 仍带旧主程序和旧助手，不能靠目标增量反向修复旧逻辑。
现有受影响用户仍可恢复官方源版本文档后升级，或使用目标整包；新策略需随后续正式版本分发。
