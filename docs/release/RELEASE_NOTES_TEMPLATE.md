# Release Notes 编写规范与模板

`docs/release/RELEASE_NOTES_vX.Y.Z.md` 是面向普通用户的发布说明，不是开发记录、验证报告或架构文档；技术证据统一写入 [PACKAGING_INDEX.md](PACKAGING_INDEX.md) 等维护文档。

## 编写要求

- **仅写本版变化**：只写目标版本相对**上一个正式发布版本**的新增、优化与修复，不把更早正式版已有功能、历史候选或实验记录重新混入。
- **语言与文风**：默认使用简体中文（除非明确要求，不附英文版）；若用户给出示例或认可过特定文风，以该文风为准。
- **精简栏目**：正文仅保留确有内容的「新增」「优化」「修复」「升级说明」「下载选择」，无内容的栏目直接省略，不凑条目。
- **用户视角表达**：每栏通常 2～4 条、最多 5 条；每条只表达一个用户可感知的变化，优先说明“用户得到什么”，合并同类项。
- **隐藏内部实现细节**：除非用户操作确实需要，不写 DXGI/LUID、CUDA 序号、PCI、ABI、错误码、内部类名、测试数量、哈希、构建日期等实现或验收参数。
- **固定栏目约定**：
  - 「升级说明」只写用户必须执行的动作；
  - 「下载选择」**逐字采用下方模板中的四项句式**，不自行缩写、改写推荐人群或下载用途，也不在四项之后附加额外固定说明段落。
- **打包同步检查**：打包前先定稿源文件；`scripts/package_editions.py` 复制到 `editions/` 和 `github-assets/` 后确认三份文件一致。纯文案修正无需重压三种大 ZIP。

## 标准模板（复制以下内容至 `docs/release/RELEASE_NOTES_vX.Y.Z.md`）

```markdown
# vX.Y.Z Release Notes

## 新增

- 新增……

## 优化

- 优化……

## 修复

- 修复……

## 升级说明

- 从旧版升级时……

## 下载选择

- **轻量版**：主程序，不含光流推理组件和模型，适合基础增强与超分处理。推荐第一次轻量试用下载。
- **完整版（full）**：包含主程序、光流推理组件和模型；下载全部分卷后合并解压。推荐对画质和稳定性追求的用户下载。
- **推理附加包（addon）**：为同版本轻量版补齐组件和模型；下载全部分卷，合并后解压到主程序目录，完整版无需重复安装。
- **自动升级增量包（dlssupdate）**：给次版本对应升级的快速安装包，一般是软件自己拉取或者下载失败手动拉取导入的选择，新用户请下载轻量版或者full版。
```
