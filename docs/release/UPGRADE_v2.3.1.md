# v2.3.1：更新失败时，怎样尽量不重下完整版

如果报错包含 `Installed file missing or modified` 和 `_internal/nvngx_dlssnr.dll`，说明旧更新器发现内置 DLL 与原包不一致，此时尚未替换程序文件。这不代表必须下载几 GB 的完整版。

## 已在 v2.3.0，手头还有原版压缩包

1. 关闭主程序和更新助手，保留旧目录作为备份。
2. 备份现在使用的适配 DLL。推荐放到程序同级的 `mods/nvngx_dlssnr.dll`；如果该处已有文件，先核对，勿直接覆盖。
3. 从官方 v2.3.0 原版压缩包提取 `_internal/nvngx_dlssnr.dll`，恢复到旧程序的同名位置。不要用显卡适配包中的 DLL 充当原版内置 DLL。
4. 检查设置中手动指定的运行库路径，确保指向需要的适配 DLL，然后重新检查更新。若提示清理上次失败的下载，核对确实为失败／未安装状态后通过程序确认；不要自行删除整个更新目录或备份。
5. 使用对应的 v2.3.0 → v2.3.1 lite/full 增量包。若还有其他文件校验失败，停止此办法，使用下一方案或新版整包。

恢复 DLL 不需要重下模型。原版 v2.2.2 / v2.3.0 更新器仍然严格校验；仅发布新版不会自动修好旧程序。不要单独替换更新助手，也不要把 `.dlssupdate` 当整包手动覆盖。

## 没有原版压缩包，或仍在 v2.2.2：轻量包＋复用已有组件

此方案仅适用于官方 v2.2.2 / v2.3.0 完整版或同版本轻量版＋附加包，且推理程序、依赖和模型未被修改或删除。只需下载：

- `DLSS5Tool-v2.3.1-win64.zip`（轻量版）；
- `DLSS5Tool-v2.3.1-addon-component-reuse.zip`（很小的组件说明文件补齐包）。

操作步骤：

1. 关闭程序，保留旧目录；将新版轻量包完整解压到一个新目录。
2. 将旧目录的 `mods/enhancement` 和 `mods/models` **复制**到新目录的 `mods` 下。文件夹应为 `新目录/mods/enhancement`，不要套成 `mods/mods`。不要复制旧 EXE、更新助手或 `_internal`。
3. 将 `component-reuse.zip` 解压到新 `DLSS5Tool.exe` 所在目录，允许覆盖其中列出的少量说明文件。它不是安装组件的替代品，不包含 DLL、推理程序或模型。
4. 将自用的 `nvngx_dlssnr.dll` 放到新目录的 `mods` 下。若旧 `_internal`、`mods` 各有一份不同 DLL，请先在旧版设置中确认实际使用哪份，不要盲目覆盖；新目录的内置 DLL 保持原样。
5. 启动新程序，在设置中核对运行库与组件路径，运行一键诊断，并用短素材试一次；成功前保留旧目录。个人设置、队列和输出请另行备份，此方案不自动迁移它们，尤其不要沿用指向旧目录的绝对路径。

如果旧版未装推理组件，只下载新版轻量包即可，不需要复制组件，也不需要补齐包。旧组件被修改、缺失、来自非官方包或使用自定义组件目录时，请使用本版附加包／完整版，不保证复用成功。

v2.2.2 不支持直达 v2.3.1 的增量包；上述方案是新目录安装并复用本地组件，不是跳过增量校验。安装 v2.3.1 后，后续增量在官方内置运行库不变时可以保留用户替换的该 DLL；其他文件和更新包仍严格校验。
