# Issue #14：说明文档误阻断增量升级

本页保留第一轮调查和验证历史。维护者随后要求彻底分离文档与安装强制校验，
最终实现及最新证据见 [更新器文件策略](UPDATER_FILE_POLICY_20261116.md)；
下文“五个路径、仅未变化文档例外”已被最终策略取代，不作为当前行为说明。

日期：2026-11-16。状态：本地源码修复与定向验证完成；未提交、推送、打正式整包或上传附件。

## 结论与责任

[Issue #14](https://github.com/banbanzhige/DLSS5Tool/issues/14) 报告从 v3.1.3 使用 lite 增量升级
v3.1.4 时出现 `Installed file missing or modified; no files replaced: mods/README.md`。

这是我们更新器的兼容性设计和验收覆盖问题：未变化的说明文档与运行依赖共用强制基线校验，
本地删除、清空、编辑或换行变化均会阻断整个升级。该报错路径在替换程序文件之前，拒绝事务本身
避免了半更新；错误在于将非运行文档设置成升级前提。

用户那份 README 为什么不匹配仍未知，没有其文件、哈希或安装历史，不能断言是用户修改或我们
某次自动写坏。本次未发现应用运行时改写该 README 的代码，也没有找到这两个正式包的该文件不一致。

## 已核实的证据

- 只读取得 Issue 正文（当时无评论）及 v3.1.3/v3.1.4 正式 Release API 元数据。
- 重新计算两个本地 lite ZIP 和 v3.1.3 → v3.1.4 的 lite/full 增量 SHA256，均与 GitHub 附件摘要一致。
- 两版 lite/full 解压目录、已保存的逐文件清单及两个 lite ZIP 的 `mods/README.md` 一致：
  4,747 字节，SHA256 `0fc436abfea5131243444184aba67448adc49c6de2a5c1d967245f705a7a7ded`。
- 两份增量的 before/after 对此文件记录相同，payload 都没有它；不是更新时准备替换 README 才报错。
- 使用正式 v3.1.3 的旧冻结 `DLSS5Update.exe` 和少量合成文件实际执行事务，删除 README 后得到
  完全相同的错误，退出 1、状态 failed，合成旧主程序仍为旧字节。
- 本次未重新哈希 full 的所有大分卷，也未复做全量正式包逐文件验收；以上结论限于已说明的证据范围。

小型机器记录见 [evidence.json](issue14-20261116/evidence.json)。正式旧包、正式基线和线上附件未改动。

## 当前受影响用户的处理

1. 关闭程序，备份自己的 `mods/README.md`（如果存在）。
2. 从官方 **v3.1.3** 整包只恢复同路径的该文件，然后重试原官方增量。
3. 若还有其他受管文件差异，按具体报错检查；也可在新目录使用 v3.1.4 对应形态整包，再迁移设置及自定义组件。

不能建议删除整个 mods、覆盖用户 DLL/模型、关闭 SHA256 或从未知来源下载修补文件。
旧主程序在准备阶段、旧助手在安装阶段都执行旧校验；仅重新生成目标增量不能更新已经执行中的旧逻辑。
同版本替换附件或删减清单也不是修复路径。源码修复进入后续正式版本后，才能供已安装该修复的客户端使用。

## 已实现的修复

`dlss5tool/delta_update.py` 用五个精确路径声明非运行文档：根目录的中英文 README 和更新日志，
以及 mods 与 enhancement 的 README。仅当 before/after 对某文档完全相同，容忍本地缺失、
空文件或内容差异，记录安装前实际状态；不新增 payload、不覆盖、不回滚它，并在事务结束检查状态未再变化。

本次需要更新/删除的文档仍要求准确旧字节；官方原样文档可以正常更新并留备份。
程序、助手、依赖、模型、许可及其他未知文档仍严格校验；保留路径、重解析点、硬链接、下载摘要、payload
及回滚备份检查。主程序与冻结助手共享这一模块，没有只改单边。
