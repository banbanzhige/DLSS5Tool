# 动态共享缓存 · 2026-09-09

## 当前行为

原图、DLSS画面和深度／光流原始预测共同使用界面中的“缓存预算”。
**取消上一版固定6GiB＋2GiB划分，取消引导2GiB独立上限。**
例如预算8192MiB，画面只占1000MiB时，引导可使用剩余空间；引导少或关闭时画面可使用总预算。
只改DLSS外观参数仍保留引导缓存；输出混合沿用原有无需重跑模型的后处理。

底部RAM现在是登记在共享池中的画面与引导合计，不是Python进程或GPU显存占用。
预算不预分配，缓存按需增长；超限淘汰，缓存淘汰后访问会重新推理。
总预算只限制长期缓存数组，不包含模型、CUDA／D3D12上下文、解码／编码队列、
正在推理／后处理的临时数组、当前展示帧或Python元数据。释放引用也不保证系统RSS立即等额下降。

## 实现与回收

- `dlss5tool/shared_cache_budget.py`：Windows命名映射中的小型占用表＋原生命名互斥锁；不在共享表中存图像。
  每个参与者有独立登记槽，不因多个工作进程／会话更换而覆盖别人的占用。
- 画面缓存保留现有按播放位置保护的淘汰策略；引导按LRU淘汰。它们不是两个固定分区，
  也不是声称所有条目按全局单一LRU排序；占用与可用量通过共享表动态协调。
- 留存缓存的增减在同一锁保护下记账，避免两个进程同时花掉同一份剩余预算。
  模型推理、GPU同步、帧哈希、管道等待不持有记账锁。
- 当一侧无法保留新的帧／预测，会提出最小必要空间需求，另一侧回收旧缓存让出空间，
  避免引导占满后画面缓存永久饥饿。单条超过总预算时不缓存。
- 组件每帧前及空闲时约250ms检查共享预算与媒体代次；调低预算不需要等待下一次推理。
  正在执行的当前帧必须安全结束，因此缩预算／切媒体不是强行中断推理或瞬间硬杀内存。
- 切媒体／清空媒体发出缓存失效代次，旧原始预测回收；只改DLSS参数不发送该失效信号。
- 正常关闭释放登记槽；异常进程退出由OS释放内存，其他参与者确认进程死亡后清掉遗留记账。
  权限不足时不会擅自当作进程已死。共享对象最后一个句柄关闭后由Windows回收。
- 原始帧对仍按实际内容哈希和顺序匹配，保持seek／切镜归一化规则；未加入上一轮有异常的索引缓存。
- 共享池标识只在当前运行期使用，不保存进导出队列或用户设置；旧队列加载会过滤该字段，
  执行时重新绑定当前共享池。多个来自同一GUI的导出组件也参与同一预算。
- 独立脚本没有GUI共享池时仍有显式本地预算，默认1024MiB，可设置；不再硬夹到2048MiB。
- 新GUI要求共享能力握手，旧组件不能静默忽略共享预算。需主程序代码与组件一起更新。

## 验证

真实冻结组件＋ProcessLive，RTX4070 SUPER，1088×1920原片243帧，Large720、原始RAFT6次完整输出、
深度SDPA FP16、双Stream，未改用户原片／参数文件／模型／DLSS DLL。

测试共享总预算1024MiB，另分配32MiB数组模拟画面缓存实际消费者（不是固定预留策略）：

- 首遍483次模型推理，原始引导占806.6MiB，总登记约838.6MiB，未超总预算。
- 相同参数、强度改为0.55、重复改参三遍全部命中483次，模型调用0。
- 相同参数回放和冷遍一致；改参回放与新模型禁缓存重算的243帧SHA-256全部一致。
- 本机process吞吐约7fps→23fps，含IPC／DLSS，剔除首帧；不含GUI、解码／哈希／编码，不是30fps保证。
- 暂停时将总预算缩至模拟画面占用32MiB，引导回收到0；关闭并释放画面后登记总占用0。
- 最终组件另跑36帧五遍一致性＋暂停回收，全部通过。
- 三种引导模式同步／三槽异步输出一致，非活动引导和reset清零通过。
