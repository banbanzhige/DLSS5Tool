# 推理默认参数与启用检查 · 2026-09-09

产品处理默认值取自本机用户实测后保存的参数，而不是截图中旧的 720 长边：

- 光流／深度分析长边 512，RAFT 6 次更新，反向光流。
- 深度 Large，SDPA＋FP16；混合引导使用双 Stream（单模型仍使用串行）。
- 深度平滑 0.9、百分位 1/99；光流显示量程 3（只影响可视化）。
- 本地色调／结构 1.0，NVENC p5、高质量，宿主 compatibility 提交。
- 默认不降低用户已有显式参数；不复制个人路径、窗口位置、主题或缓存布局。
- 关闭引导时保留零引导快速路径默认开启，基础版无需推理组件。

每次 GUI 启动从关闭开始，其他保存参数仍保留。队列任务自身的引导配置不被启动规则改写。

## 启用流程

用户选择仅光流／仅深度／混合时，先保持模式关闭，在后台等待旧帧结束、释放旧宿主，
然后检查所需文件、启动隔离组件、加载对应权重并完成两张 128×128 合成图的试推理。
第二帧不 reset，确保光流模型真的执行，而不是只验证首帧零光流。

仅光流不要求深度权重；仅深度不要求光流权重。验证协议、精度、执行配置及实际设备；
缺文件、坏权重、CUDA／依赖不可用、推理失败或超时均不启用。界面保留参数和错误原因，
恢复普通处理；不下载、不安装、不静默切 CPU 或其他模型。关闭模式不启动检查组件。
失败后保留对应参数的编辑能力，允许主动修正型号、精度和设备，再重新选择模式验证；
修正参数本身不会暗中启用推理。
检查中禁用冲突操作，主线程继续处理事件。试推理结束即释放独立组件，不污染媒体历史。

这是就绪检查，不是实际素材尺寸的显存保证；正式处理仍有自己的尺寸、格式和资源检查。
检查会产生一次模型加载开销，正式渲染另建媒体会话。本轮未实现预热会话移交。

## 性能工作边界

后续主线是首次渲染的分项计时、减少不必要搬运与等待、验证连续帧输入准备复用；
不以跨重启缓存、减少迭代、丢帧或更换模型冒充同画质加速。
本轮只修改基础应用默认值和启用检查，没有修改模型 forward、部署推理加速或接入 NVOFA。
既有共享内存、原生上传和双 Stream 优化不重复计为本轮新增收益。

硬件烟测：`.venv/Scripts/python.exe scripts/guidance_activation_probe.py`。
使用临时设置与队列、隐藏 Tk 窗口和合成输入，不修改原片、用户设置或模型组件。

本机 RTX 4070 SUPER、现有冻结组件已通过三模式的真实试推理与关闭检查；
最终一轮检查耗时约 5.6／10.4／11.0 秒，主窗口事件间隔最大约 235ms。
这是模式启用耗时（含模型加载），不是逐帧渲染性能，也不代表其他显卡。
CPU 回归另外覆盖默认值、旧参数保留、缺文件／旧协议／内核失败、检查中不启用、
失败回到关闭、无素材重试、浅／深色内联提示及并发切换防护。

## 硬件光流的成本

NVOFA 使用受支持 NVIDIA GPU 的专用光流硬件，不是需要额外权重的新神经网络。
所需接口运行库由显示驱动提供；软件需适配接口并检测具体 GPU／驱动能力。
现有独立原型调用驱动 DLL，未引入另一套 Python 推理包或替换 DLL。
正式集成体积尚未测量；如果继续保留 RAFT 备选和深度模型，原推理组件不能因此删掉。
主要风险是运动估计结果不同导致的遮挡、细节与时序质量差异，而不是必须再下载大模型。
