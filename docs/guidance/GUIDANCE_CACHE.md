# 调参引导缓存 · 2026-09-08

> 此页为第一版固定分区缓存的历史验证。2026-09-09已改为动态共享总预算，取消2GiB独立上限与四分之一预留；当前说明见 [docs/guidance/GUIDANCE_SHARED_CACHE.md](GUIDANCE_SHARED_CACHE.md)。下文预算与部署哈希不代表当前版本。

## 使用

已接入开发版并更新根目录`mods/enhancement`组件。启动／重启`run.bat`，保持原来的深度与光流设置即可。
日志显示“原始预测缓存已启用（上限 … MiB）”。首遍照常推理；之后改强度、风格、本地结构等DLSS外观参数，
命中缓存的帧不再跑深度和光流模型，只重新执行必要的引导后处理与DLSS。
首次处理不因缓存变成实时，不承诺30fps。

若日志提示组件不支持缓存，需要更新组件；旧组件仍可工作，但没有缓存收益。
只替换模型权重不会使旧组件具备缓存。已打包的旧主程序EXE需重新打包才能使用新预算／提示逻辑。

## 范围与失效

- 会话内RAM缓存，不写磁盘，不跨程序重启保留。
- 保存低分辨率float32原始深度预测和原始光流，不用JPEG或FP16有损压缩。
- 键包含实际RGBA字节SHA-256、尺寸和dtype；光流还包含有序上一帧／当前帧身份。
  不按文件路径或帧号猜测命中。即使源文件被替换，实际像素变化也不会返回旧预测。
- 模型实例固定权重、编码器、精度、引导长边和方向。引导设置／预算变化、模型会话重建会清空缓存。
  这一版保守地重建整套引导，不实现“换深度后保留旧光流”的跨会话共享。
- 更换媒体后，相同实际输入仍可安全命中；不同内容必定重新推理。关闭／清空媒体释放会话时释放缓存。
- seek、首帧、切镜仍清零光流／重置归一化状态。深度百分位与时序平滑**每次重新执行**，
  不缓存归一化结果或使用前轮有异常的帧号／百分位捷径。
- 模型异常即废弃会话并清缓存；不返回半完成结果。只允许同一Models实例一次处理一帧。
- 模型文件在磁盘原路径被替换后，运行中的模型仍是已加载版本；需刷新／重建会话载入新权重。

## 内存预算

GUI从原总缓存预算中预留四分之一、最多2048MiB，剩余供原图＋DLSS画面缓存使用。
例如8192MiB分为6144MiB画面＋2048MiB引导；预留不会立即分配。
该预留在模式切换／组件释放时保持稳定，防止旧组件还在退出时重复占满预算。
现有预览性能区域显示预算说明；底部RAM仍显示画面缓存使用量及其子预算，不是进程总内存。

引导缓存采用按字节计数LRU：超限先淘汰最久未使用项，单条大于预算不缓存；淘汰后访问重新推理。
长片超过容量后不能保证第二遍零推理。预算针对缓存数组，不包含模型、CUDA上下文、解码器、IPC缓冲、
短时在途读回／后处理数组及Python元数据，因此不是整程序RAM硬上限。
无GUI的直接调用默认1024MiB；内部`guidance_cache_mb=0`可禁用，最大2048MiB。
并行导出每个独立进程有独立缓存，不能把单会话预算理解为所有导出进程的合计预算。
