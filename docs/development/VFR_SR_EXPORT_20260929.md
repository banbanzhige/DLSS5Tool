# 纯超分变帧率导出修复（2026-09-29）

## 原因与处理

GUI 的纯超分和插帧共用渲染缓存。此前缓存入口无条件执行插帧的恒定帧率校验，
导致仅启用超分时也拒绝变帧率视频。缓存编码器接收 rawvideo，默认按固定帧率写出，
所以直接跳过校验会改变画面时间线。

现在仅在插帧倍率为 1 时允许严格递增、从零开始的变帧率时间戳。逐帧超分后，
常规 FFmpeg 写入器先编码无 B 帧视频，再用 PyAV 18.1.0 按原始 PTS/DTS
无损重封装编码包，最后沿用原有音轨封装策略。不会生成或丢弃源帧。
插帧倍率大于 1 的路径仍拒绝变帧率；时间戳倒退、重复、非零起始偏移也仍拒绝。
变帧率纯超分需要环境提供 PyAV；缺失时给出明确错误，不自动改为固定帧率。

## 验证

- 用户反馈素材：121 帧，50 ms 与约 33.33 ms 间隔交替；原视频 1112×834。
- 纯超分共享缓存路径完成 2× 导出：2224×1668、121 帧、0 生成帧。
- 输出 121 个画面 PTS 与原片逐帧一致；视频时长同为 5.016667 秒，原音轨直通，音轨时长同为 5.085011 秒。
- 时间戳写入器、缓存及插帧拒绝边界的自动化测试通过。

此修复仅在源码环境验证，未打包或更新现有发行版。
