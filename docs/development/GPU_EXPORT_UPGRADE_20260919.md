# GPU 导出升级：本地接入与验收 · 2026-09-19

## 已交付到本地源码

此前缺口已实际接通：**HDR图像GPU转换、真实HDR插帧、普通DLSS增强显存输出、音视频封装、
独立编码进程与应用导出入口**。不再只提供整数YUV测试接口。

本机新增 `runtime/gpu-export/` 组件集（约805KiB），不覆盖原正式DLL/worker。
`manifest.json`固定组件与FFmpeg哈希；不是每次导出从tmp寻找实验文件。
GUI、缓存导出、引导图导出及分段导出调用统一选择入口。

自动选择刻意受限：**至少1080p、不在编码器内缩放、BT.2020 PQ/HLG、P5、高/均衡质量**。
其余设置保留原FFmpeg路径，在首帧前决定，不在运行中降画质、换编码器或丢帧。
实测CPU来源SDR和小图新进程较慢，所以不为“全开”而默认启用它们。
组件缺失或FFmpeg版本哈希变化时保留原路径；注册组件损坏明确报错。

直接导出主循环还支持SDR/HDR的2×/3×/4×显存生成帧消费，以及不插帧、不缩放、mix=1、
单槽非分块普通增强的显存输出。缓存、预览、其他混合/比较/缩放仍保留现有算法及所需CPU图像，
**没有声称所有处理都在GPU，也没有修改RAFT/NVOFA/VSR算法、插帧时间位置或reset历史。**

## HDR困难已经解决

FFmpeg7.1.1原命令的实际协商为RGBA64→GBRAP16→swscale→P010；最终矩阵/色度滤波并非
直接套zscale浮点矩阵。新内核独立实现匹配的整数矩阵、双三次色度滤波与取整。
每帧2个转换内核、一个水平色度中间缓冲；滤波表只在初始化时由CPU计算上传。
RGBA16F/32F、奇数尺寸补黑边和输入行距均有明确合同。
生成HDR帧额外GPU有效性检查只回读4字节标志，保留NaN/Inf/越界停止的原规则。

普通DLSS增强复用原 `dlssnr_process` 计算/指导/重置逻辑，仅在显式GPU事务中将末端复制目的地
从CPU readback换为共享DEFAULT堆；父进程同步消费后才允许下一次处理。
普通处理接口的readback不变。新增宿主在独立NGX进程加载，原宿主仍保留。

## 稳定性和应用入口

`ProcessGpuVideoWriter`在独立进程拥有CUDA/NVENC，父进程共享内存传CPU帧、句柄传GPU帧，
不把进程内CUDA指针当跨进程地址。调用串行加锁，兼容GUI后台写入线程。
每次请求有超时/取消检查；Windows kill-on-close Job清理编码worker及其FFmpeg子进程。
每个任务有独立发布事务目录：成功才rename，失败/取消只清理本任务文件，不覆盖已有输出。
这覆盖正常取消/显式超时路径，**不是驱动设备移除故障注入或所有Windows版本认证**。

### 性能观测（不是整项目通用加速比）

自动选择路径：1080p、30秒/720帧**重复渐变图案**，包含写入器启动、转换、编码与MP4封装，
不含DLSS推理/解码；未独占GPU，不据此推算用户任意长片。

| 测试 | 原FFmpeg两轮 | 新路径两轮 |
| --- | --- | --- |
| PQ | 27.314 / 27.279秒 | 4.496 / 4.526秒 |
| HLG | 26.452 / 27.965秒 | 4.714 / 4.730秒 |

此前96帧SDR1080p测试：原路径约0.75～0.77秒，新路径1.21～1.25秒；因此SDR CPU来源不自动切换。
短片小图也保持原路径。显存来源SDR的收益取决于上游搬运，不混用这些数据。

## 如何使用和回退

本机源码GUI正常导出满足条件的HDR会自动选新写入器，无需新增面板。
显存生产者直连可以通过已有导出主循环调用，并可显式运行：

```powershell
.venv/Scripts/python.exe -B -m dlss5tool.frame_generation input.mp4 output.mp4 --multiplier 2 --gpu-worker runtime/gpu-export/frame-worker.exe --gpu-encoder runtime/gpu-export/encoder.dll --gpu-sdr-ptx runtime/gpu-export/sdr-yuv.ptx --gpu-hdr-ptx runtime/gpu-export/hdr-yuv.ptx
```

普通增强用 `--multiplier 1 --enhance --gpu-host runtime/gpu-export/enhancement.dll`。
输入/输出实际路径由使用者选择，已有目标不会覆盖。变帧率仍按原规则拒绝，不自动重定时。
把manifest的`enabled`设为false可关闭自动路径；原运行库从未替换。这里只说明回退，不自动执行。

## 发版边界

本次是**本地源码升级，不是发版**。没有更新版本号、打整包/增量包、上传Release。
新增PyAV18.1.0 wheel的媒体DLL返回LGPLv3-or-later，且捆绑多个编解码依赖；许可证与相应来源
材料不能只拷贝PyAV的BSD许可就声称完整。打包脚本已经接组件收集，但manifest的
`packaging_license_review_complete=false`会阻止把尚未完成再分发材料检查的组件误打进发行包。
正式打包时必须完成该材料检查，并仍遵守仓库增量更新固定工作流。没有绕过策略或缩减支持版本。
