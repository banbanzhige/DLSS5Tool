# 超分导出速度统计、拷贝优化与预检 · 2026-10-22

## 范围与状态

按维护者本轮选择完成：真实 FPS/ETA、超分实际缓存链路测量与保持画质的
拷贝优化、导出前资源建议。部分成果保全、自动分段与断点续导不在本轮范围。
没有修改版本号、安装程序、模型、驱动或发行包，没有发布或上传。

## 实现

- `encode_cached` 单独报告实际完成写入的输出帧数；综合百分比继续服务进度条，
  不再当成视频帧数。`FrameRate` 使用首帧之后的滑动观测，至少两秒及两个帧间隔后
  才显示速度和剩余时间；重复状态回调不增加帧数，封装／音频阶段明确显示收尾。
  统计的是编码器已接收的帧，不宣称文件已落盘或具备恢复能力。
- 阶段诊断包含 SR/NR 初始化、解码、SR、NR、合成、缓存快照、上游等待、编码转换、
  写入和收尾。采用墙钟计时，各缓存层可重叠，不能相加当作 GPU 内核耗时。
  阶段只存汇总，系统空闲 RAM/提交余量每两秒至多采样一次、最多保留 64 项，
  诊断大小不随总帧数无限增长。系统趋势不能归因到某个 SDK 泄漏。
- 去掉 SR 返回的自有快照后的第二份整帧复制；无 FG 时不再复制不用的上一帧和
  生成 FG 专用分析副本。需要 FG 的历史仍保持独立快照。
- 缓存只有在输入来自上游 `RenderPair`、对象身份完全一致、只读且连续时才共享
  已拥有的 ndarray；任意外部数组和 IPC 传输槽仍建立自有快照。下游持有强引用，
  上游淘汰不使其失效；每层继续完整计入逻辑预算，不通过少记内存扩大队列。
  同一帧对内相同对象只复制和计数一次。
- 单次视频导出和任务队列开始前预检分别提示 RAM 峰值、显存不足／余量偏紧、
  超过 4K、查询未知以及长时间超分风险。10 分钟仅为提示长任务的界面阈值，
  不是硬件容量或故障时间界限；不会按时长乘出一份“整片显存”。
  同一风险配置在当前程序内确认一次，资源风险类别变化重新提示。
  估算不包含全部模型／驱动工作区，不承诺通过；时长分割不能解决单帧资源不足。
  建议同源短片试导，必要时自行分割；提示边界可能变化，并保留用户是否继续的选择。
- 关于中的诊断报告附带最近一次预检和导出性能（成功、失败或取消），界面日志输出
  阶段汇总与历史重算、复制／共享字节量。缓存会话诊断是该会话整个生命周期的计数，
  不伪装为只属于本次导出的统计。

## 实卡测量

环境：RTX 4070 SUPER，驱动 617.42，64 GiB RAM，Python 3.13.3；固定合成 SDR
移动图案，30 FPS，2× 空间超分，无光流／插帧，NVENC P5/high。使用实际 GUI 的
`RenderCache → encode_cached` 路径，不以旧的单独同步 SR 方法代替。
输入／输出帧哈希的审计开销在各轮都保留。帧率取第 5 个输出帧后至最后一帧的区间；
不含模型启动和收尾，不是整段任务端到端倍数，也不是 GPU 利用率。

| 用例 | 修改前输出 FPS | 修改后输出 FPS | 结果与边界 |
| --- | ---: | ---: | --- |
| 960×540 → 1080p 纯 SR，48 帧 | 32.88 | 53.91 | 48 帧编码前哈希全部一致；只有一对短测 |
| 1080p → 4K 纯 SR，24 帧，第一对 | 7.38 | 8.87 | 24 帧编码前哈希全部一致 |
| 同一 4K 用例，逆序复核 | 7.32 | 10.21 | 24 帧编码前哈希全部一致；原版通过 Git HEAD 独立加载 |
| SR+NR → 1080p，48 帧，两轮 | 24.77 / 20.30 | 24.87 / 24.75 | 存在运行间波动，不宣称固定加速比例 |

4K 纯 SR 采样到的进程私有提交合计最大值从约 2313／2342 MiB 降至
1543／1531 MiB。采样包含主进程及已登记的 SR/NR worker，未覆盖 FFmpeg，
每秒采样不能当作真实瞬时峰值。这些短测不能证明小时级内存稳定。

两次原版 NR 本身的编码前输出哈希不完全一致；新旧实卡对照进入 NR 的输入
48 帧哈希全部一致，但 NR 输出跨次不同。本轮不宣称实卡 NR 跨运行逐 bit 一致。
所有权与缓存转换还通过 RGBA8、RGBA16F、float32 定向测试和原有 SDR/PQ/HLG/scRGB
处理测试，未改变推理设置、时序重置、精度、超分档位或合成公式。

本轮一项原版 4K SR+NR 探针在第一个编码帧后触及预先登记的 4 GiB 进程私有提交
安全限额而停止（采样约 4106 MiB），保留为失败，没有上调限额将其包装为通过。
最初一项纯 SR 探针已完成输出，但诊断脚本在读取已关闭的 multiprocessing 对象时
失败；修正脚本后重新建立基线，该次不作为有效性能证据。
