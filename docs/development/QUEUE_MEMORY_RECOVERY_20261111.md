# 内存压力后的队列恢复 · 2026-11-11

本次复用既有内存预留、缓存回收、共享额度和工作进程 Job，补齐**压力退出后回收、等待、重建、
有限重试当前队列项**。没有替换运行库、降低画质或调整既有安全预留。

这解决的是队列恢复衔接，不是宣布原生内存增长已根治，也不代表 P0 长稳平台验收通过。

## 之前缺在哪里

- NR／VSR 已能传递内存压力响应，但父进程抛出普通异常后丢失结构化信息。
- 部分 GUI、跨线程错误快照及 GPU 导出协议又把错误压成文字，队列无法区分可恢复的压力与普通错误。
- 队列会把当前项记为失败并继续；同尺寸复用时还可能再次遇到已退休的会话。
- VSR 使用零字节命令分配量。原空闲判断把“可用额度为零、需要额度也为零”当作足够，跳过压力退出。

## 完成后的行为

1. **只识别结构化 RAM／Commit 压力。** 保留阶段、所需额度、来源进程等标量信息；不靠匹配错误文字
   触发重试。普通输入错误、设备故障等仍走原有失败处理。
2. **先退休旧所有者。** 停止预览生产，回收 NR、VSR、共享渲染与相关输出消费者；复用已有清理重试。
   失败所有者和未释放额度继续保留，不不断叠加相同清理动作。
3. **确认余量后恢复。** 每 250 毫秒刷新系统内存，沿用既有物理／提交预留；所需空间取已报告的
   required／recommended 最大值，并增加既有 2×RECOVERY_MARGIN（256 MiB）恢复余量。
   连续满足既有 0.5 秒稳定窗口后才重试；未知快照不能自动放行。
4. **限制恢复次数。** 每个队列项最多自动重试两次，即包括首次在内最多三次执行；每次最多等待 120 秒。
   超时或用尽次数后暂停队列，后续项目保持等待，已完成项保持完成。
5. **可以暂停或取消等待。** 暂停保留当前项待处理，取消标记当前项已取消；旧会话尚未退出时，
   既有 GPU 准入也会阻止新预览／导出等工作。手动再次启动队列会先重试清理。
6. **复用原有持久化和输出规则。** 不重放完成项，不覆盖已有文件；恢复时重新执行当前项，
   沿用现有输出唯一命名、编码中止和事务规则，没有新增任意文件删除。

自动重试次数属于本轮队列运行；用户手动恢复／重试时开启新一轮预算。
等待时任务仍以运行中及“等待内存恢复”进度文字保存，程序意外结束后沿用原有 interrupted 恢复规则。

**视频当前为整项重新处理，不是从中断帧接着编码。** 中途续导、预热去重、VFR、音轨和时域质量
仍需独立实现与验收。长视频若再次遇到同样压力，有限重试后会暂停，不会无限循环。

## 对现有保护的补漏

`receive_worker_command` 在空闲时至少检查一字节可用额度，修复 VSR 零分配量跳过保护的问题。
活跃命令的实际分配计账仍保持零，不虚增每帧预留；stop／close 命令仍可在压力下接收。

工作进程压力经 NR、VSR、GPU writer、resident SR 协议传回；跨线程 `ErrorSnapshot` 只增加白名单标量
压力数据，不保留原始异常、NumPy／CUDA 对象或 traceback 帧。已消费过的退休错误也能在后续读取中保留原因。
NR 初始化阶段若收到结构化压力，会直接交给恢复流程，不再尝试分配另一个后端。

## 验证

- 最终关联测试：**224 passed，89 subtests passed**。范围为队列、压力协调、所有者生命周期、
  关联导出协议、GPU 准入及中英文文本，没有运行全仓库回归。
- 新增恢复用例覆盖：异常／结果字典两条传递路径、图片／视频整项重试、普通错误不重试、次数用尽、
  等待超时、未知／波动余量、取消／暂停、回收失败保留所有者、完成项不重放、错误不持有帧数组，
  以及零分配量工作进程的软线／临界线空闲退出。
- 最终真实 NR／VSR 验证约 **39.7 秒**，两者均经历：真实首帧 → 仅在子进程内注入低内存快照 →
  自动压力退出 → 正常队列恢复回调 → 新工作进程 → 当前项完成 → 后续项完成。
- 两种运行库均只重试一次；新旧进程身份不同，同一输入前后输出 SHA256 一致；完成项的既有输出未改变。
- 最终监督进程退出码为零，所属 Job 无残留进程，没有监督器兜底清理；测量期间源码和运行库清单前后相同。

真实探针使用无界面回调夹具和小型导出适配器，队列调度、恢复回调、所有者关闭及 NR／VSR 运行库为真实实现。
图片 GUI 结果传递另由单元测试覆盖。这不是完整可视界面验收、真实耗尽 RAM、完整视频导出或整夜挂机测试。

### 失败记录和旧测试隔离

初次真实探针中 NR 恢复通过，VSR 因上述空闲判断问题未退出，整次记录为失败；修复后两次复测均通过。
原失败记录保留，不能计入最终通过。

首次关联测试有一个既有缓存断言失败。用修改前 `cfc58fc` 源码作有效对照，同一用例同样失败：
它名为 unpooled，却自动加入了先前测试留下的默认共享池，受共享池恢复滞回影响。
本次仅把该测试的构造过程显式隔离为无共享池，保留原有 512 → 0 → 512 的全部断言；产品缓存策略不变。
修正隔离后，最终关联测试全部通过。

另一次基线复核脚本曾缺少多进程入口保护，产生递归测试结果；该批结果明确标为无效，不用于证明产品回归。
入口修正后的有效基线与当前版本均复现了上述单个缓存断言，再据此修正测试隔离。
