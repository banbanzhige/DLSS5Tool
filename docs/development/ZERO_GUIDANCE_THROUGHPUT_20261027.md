# 零引导预览与导出吞吐排查

日期：2026-10-27（Asia/Hong_Kong）；起点：`c53794b`，开始时工作区干净。

## 结论

本地设置确实是 guidance_mode=0、零引导快路径开启、merged 提交和 3 帧队列。
本次没有启动光流/深度模型。当前原片 1440×2160、48 fps、369 帧。
NR 单独仍接近百帧；完整预览和导出的等待、解码回传与外观合成需要另行计算。

查明并修正两个问题：

1. `SharedCacheBudget.under_pressure` 将健康的已准入处理预留也视为内存压力。
   NR 预览因此反复缩小前向范围并进入 250 ms 等待，破坏解码与 NR 重叠。
   现在只有等待准入或仍在回收恢复期才暂停预取；已准入预留仍从缓存额度中扣除，
   物理 RAM/提交余量、优先级、回收确认及安全余量未放宽。
2. SDR 合成/编码进行了多余的 NumPy 整帧复制和通道重新装填。
   原生 RGBA8 结果直接保留自己的存储并恢复原图 alpha；三通道打包使用精确的
   OpenCV 通道转换。模型、效果参数、编码器策略、分辨率、帧率和位深保持相同。

本轮修正不等于所有完整流程已恢复 100 fps。当前用户的阴影结构 1.77、反射辉光 1.4
会启用额外合成，GPU 解码还需要将视频帧回传到现有 CPU BGR 接口；这些成本仍存在。
当前原片像素数也比历史 1080×1920 样本高 50%。

## 分层测量

GPU 运行顺序执行，复用 `.venv` 和现有 runtime；没有复制开发环境或修改用户设置。
时间是墙钟时间，各并行阶段不能相加当作 GPU 内核耗时。

| 范围 | 结果 |
| --- | --- |
| 当前原片、暖机原生 NR、3 帧队列、160 帧 | 98.73 fps |
| 相同窗口、ProcessLive、3 帧队列 | 97.19 fps |
| 当前原片、96 帧单独 GPU 解码 | 103.14 fps，约 9.70 ms/帧 |
| 120 次健康内存准入开销 | 平均 0.202 ms，p95 0.276 ms |
| 实际 GUI 自动预览、原始代码、前 64 帧 | 稳定约 13.03 fps |
| 修正预留误判、相同预览范围 | 35.15 fps；最终复核 32.60 fps |
| 当前参数完整导出、369 帧、原始代码 | 26.26 秒，包含冷启动和收尾 |
| 相同参数、复制优化后完整导出 | 17.10 秒，包含冷启动和收尾 |
| 合成/写入阶段平均时间（舍弃前 4 次） | 44.71 → 23.05 ms/帧 |

另一轮复核导出为 18.87 秒、稳态编码提交 36.37 fps；该轮与 CPU 测试部分重叠，
不是严格独占的第二组成对 A/B，不将两轮包装成固定提速承诺。
暖机 NR 和稳态处理统计不含约 6 秒宿主启动；不能与整段任务平均 FPS 混用。

### 画质验证

- `export-before.mp4` 与 `export-after.mp4` 的整文件 SHA256 完全相同：
  `0B0DA6285057355102D9C6FBDA86D7293C56861454CB04E4738980D020D6CCA2`。
  此结论仅指这一组成对运行，不声称 NR 跨任意会话恒定逐 bit。
- RGBA、RGB、BGR、非连续 RGBA 四种真实 GPU 合成输入，与提交前函数进行交替对照，
  96 次调用全部逐字节一致，包括非不透明 alpha。
- 上述四种输入的原生合成封装平均时间分别从 18.08、34.67、30.45、19.32 ms，
  降至 8.75、10.82、10.71、14.33 ms。此测量不包含 NR 和编码。
- 5 个诊断输出均通过 ffprobe：1440×2160、369 帧、48/1 fps，没有通过丢帧提速。

## 对照与边界

仅在隔离设置中将外观合成恢复中性，保留 NR 基础控制，当前原片导出为 15.31 秒，
稳态编码提交 48.89 fps。这是定位额外效果成本的 A/B，没有更改用户的阴影/反射参数。

历史记录 `ZERO_GUIDANCE_PERFORMANCE_20260912.md` 的约 98 fps 对应 1080×1920、
480 帧暖机编码到 null、无音轨封装及 MP4 落盘。相同旧素材与探针在当前环境重跑为
67.53 fps，ProcessLive 单独为 118.89 fps。不能说历史百帧已经完全恢复。
NGX DLL SHA256 与旧记录一致，宿主 DLL 已从历史 F630… 改为 C8AD…；本次没有冻结旧宿主/
驱动做完整同环境交叉验收，因此未将全部历史差异归因到某一项修改。

尝试将 GUI 轮询间隔从 16 ms 缩至 4 ms，没有收益（约 33.79 fps），未更改默认间隔。
已有 GPU 合成到编码接口的隔离探针约 16.39 秒，单次结果不足以证明稳定端到端收益，
本轮未改变产品的编码路径选择。
