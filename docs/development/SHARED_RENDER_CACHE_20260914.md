## 已接入的路径

普通视频预览启用超分或插帧时，使用同一个全画质管线：

`源视频解码 → RTX 超分 → DLSSNR/所选引导＋强度混合 → 最终尺寸 → 基础帧缓存 → NVOFA＋DLSSG → 输出帧缓存`

基础层每源帧处理一次；插帧关闭时直接消费基础层。原图参考与处理结果成对缓存，
插帧开启时两侧分别插帧；对比线、差异显示由消费端合成，不送入光流/插帧。
SDR 为 RGBA8，HDR 为 RGBA16F。预览仅在显示时映射到 SDR/缩放，导出消费原精度数据。

沿用原播放器、时间轴、逐帧、暂停、缩放、对比、导出和批量队列；不新增面板。
时间轴仍以源视频位置计，逐帧按钮按输出帧移动，可以查看生成帧。
按输出帧率定时呈现；缓存不足暂停音频并缓冲，恢复时重新锚定音画位置，
不以重复/跳过生成帧掩盖推理不足。UI 状态栏显示帧位置、缓存量和缓冲状态。
UI/UX 技能指导了原位置反馈、主线程不等待 GPU、保留键盘操作与取消入口。

## 缓存契约与边界

- `render_cache.py` 管理一个活动配置的基础层与输出层，绑定现有 SharedCacheBudget 账本。
  账本只管理预算，像素存在本进程内；不是跨进程像素缓存，更不是磁盘持久缓存。
- 有插帧时两层各获得缓存上限的一半，无插帧时基础层使用全部上限；
  还服从其他引导缓存的共享额度。运行库/模型工作集、编解码器内存不计入像素缓存上限。
- 源文件身份（规范路径、大小、纳秒修改/创建时间）、处理参数、实际 DLL/模块/权重身份
  组成缓存键。编码器画质/码率/容器、UI 语言、视图及窗口尺寸不使像素缓存失效。
- 只改插帧倍率保留超分＋增强缓存；改超分倍率、增强或输出混合等像素参数重建基础层和下游。
  基础层当前不再细分为独立超分和 NR 两个缓存，改变增强参数不会复用旧超分帧。
- 后台按顺序处理、有限前瞻，目标附近优先保留；缓存不足一个全精度帧对明确报错，不降低精度。
- 被淘汰的历史/拖动留下的缺口从源起点恢复模型状态，不把无历史的推理当成正确结果。
  缺口补齐后停下，已有缓存尾部不因预取被顺带重算。切镜边界由基础层传递到插帧层。
- 导出逐帧读同一 session，命中直接编码，缺口补算；报告命中帧和实际新增计算数。
  已有输出/源片不覆盖，失败/取消终止编码并移除本次 staging，缓存可继续预览。
- 配置切换、清缓存和关闭在后台等待旧 worker 退出；Tk 只轮询结果，不等待 GPU。
- 队列保留每项自己的配置；不同配置切换不复用不匹配的像素。关闭应用释放全部本次内存缓存。
