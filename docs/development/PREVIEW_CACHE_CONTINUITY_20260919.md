# 预览显示交互与预缓存连续性修复

日期：2026-09-19。范围：桌面预览交互；不涉及导出算法、发行打包。

## 原因与修复

原有对比线、导航和平移事件调用 `pause()` 与 `_freeze_preview_cache()`，
不仅停止播放，还停止预渲染、递增任务代次并清空待处理队列。
已完成缓存并未整体清空，但旧代次的在途结果会被丢弃。
缩放、暂停时的窗口重绘和 DLSS／对比切换也复用了这一流程。

现统一区分显示变化与处理内容变化：

- 对比线（直接拖、Shift 拖、画面内横拖）、缩放、平移、导航小窗：
  不暂停播放，不冻结或重启预缓存；释放鼠标也不干预其他操作的恢复计时器。
- 窗口缩放、全屏切换、分离／停靠及主题刷新：沿用合并重绘，取消预缓存冻结。
  显示缓存未命中时走 fast 展示，避免移除冻结后引入界面线程同步推理。
- DLSS／对比切换：复用活动生产者；从原图返回处理视图、且没有活动或待启动任务时，
  才调度异步预览。保留原图模式停止普通后台预渲染的既有策略。
- 导出设置：以当前实际启用的预览效果、HDR 模式和有效输出尺寸判断是否刷新。
  容器、码率、编码质量、编码预设、导出并行／缓冲设置和重复 FocusOut 等事件不暂停预览。
  禁用预览的插帧倍率只影响导出；共享预览实际像素配置变化仍刷新。
  插帧倍率 1↔2 等共享／普通管线切换仍重置对应缓存及帧索引。
- 文件拖入悬停／离开不停止预缓存；真正导入换源仍执行原有失效流程。

没有移除时间轴寻址、真实处理参数修改、换源、主动清理缓存、错误处理所需的停止逻辑。
保留原有外观、键盘缩放和单击播放／暂停行为。

新增 `tests/test_preview_interaction_continuity.py`，使用真实 App 事件处理函数：

- 暂停／播放状态下的显示操作矩阵，断言生产标志、队列对象、任务代次、停止事件、
  解码计时器、预览尺寸、播放时钟和音频状态不变。
- 不抢先恢复其他操作持有的冻结；不替换已有异步启动计时器。
- 共享超分／插帧会话保留、实际导出控件刷新回调、无效重复事件、有效像素变化，
  以及导出／队列期间的保护。
- 真实 `_prefetch_job` 线程 + 受事件控制的模拟渲染器：一帧执行期间进行显示交互，
  释放后两帧均成功存入缓存，验证在途结果没有丢弃、后续任务没有停止。
- 原有时间轴、换源、缓存清理、延迟、错误处理与音频时钟测试继续通过。

新增测试中曾使用大于原图的输出框验证尺寸变化，但项目输出规则不允许该操作放大图像，
因此不会产生实际尺寸变化。已改用实际缩小的输出框，并单独增加“等效输出尺寸不重启”验证。

边界：这是事件与线程级自动化验证，不是实际 GPU 连续拖动、完整应用窗口或打包版实测。
全屏／分离／主题等路径共用已测重绘入口，未逐个打开真实窗口验收。
