## 3. 显存热缓存：收益与风险先评估

### 当前判断（推断，未做本轮实测）

不能承诺提升大。RAM 缓存已经能免去命中帧的 RAFT 推理，显存热缓存主要再省去上传/部分转换与同步，**不是再次省掉一次模型推理**。
首次连续处理且几乎没有复用时，缓存可能收益很小；反复拖动、预览和调参时更可能受益。
若最终画面缓存已命中，根本不会再次请求光流，此时增加显存光流缓存也没有额外收益。

风险主要是显存占用与缓存失效/所有权，不是算法本身：

- 显存挤占 RAFT、DLSS、超分和插帧空间，可能引发 OOM 或反而更慢。
- 缓存键不完整会把其他帧对、方向、尺寸、参数、模型或显卡的数据当成命中，直接影响画面。
- 驱逐仍被 GPU 使用的张量/缓冲会造成竞态；缓存清理、切换素材、重建会话需等待正确的消费完成。
- 保留独立不可变 FP32 原始结果原则上不应改变数值；不能用 FP16 压缩、改变推理精度或复用可覆写传输槽来冒充无损缓存。

## 4. 异步同步：先证明不改变连续历史

### 与此前分段问题的区别

此前分段方案是多个独立 DLSS 会话分别从片段起点开始，历史不同；已有实测表明额外预热并不能保证各段光影一致。
参见 [队列与光影一致性研究](QUEUE_AND_FLOW_STUDY_20260912.md) 的“时序历史与分段拼接”。

本方向如果仅替换同步机制，应保持**同一个 DLSS 会话、同一帧序、同一 reset 序列、同一组输入字节**，不拆段、不额外重建会话。
这在设计上不同于分段拼接，但绝不等于“改成异步就一定安全”：错槽、提前覆写、漏等 fence、reset 与帧错配仍会造成错误画面。
也不能假定 RAFT 与 DLSS 在同卡并发就更快，它们可能竞争 GPU 资源。

### 强制不变量

- 不新增多段独立 DLSS 会话，不改变帧顺序，不增加/删减 reset，不用跳帧/重复帧或近似光流换速度。
- RAFT 自身有可变相关性状态；不能让同一个模型实例无保护地同时处理多个帧对。
- CUDA 完成写入后 D3D12 才能读；D3D12 完成消费后 CUDA 才能覆写/回收。每个槽的序号、fence 值和所有权必须对应。
- 不随同步改动一并更换 resize、尺度换算、half 转换或模型精度，保持上一轮修正过的数值语义。
- 遇到设备异常或序号错误停止该会话，不静默使用旧光流或空向量继续输出。

### 待办与验收门槛

- [ ] 先证明当前 CPU 等待确为值得优化的瓶颈，再考虑 CUDA 外部 semaphore / D3D12 shared fence 原型。

- [ ] 用同一批预先算好的原始光流隔离测试同步正确性；再用真实连续 RAFT 推理做端到端测试。

- [ ] 连续处理长于历史短测的片段，覆盖暗场、肤色、曝光变化、快速运动和切镜，不能只测片段首帧或平均 MAE。
