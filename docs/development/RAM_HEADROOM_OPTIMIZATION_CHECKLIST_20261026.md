# 内存保护与缓存协调优化清单 · 2026-10-26

状态：**M1～M9 已完成源码实现与本机定向验收**。本清单保留对齐时的实施顺序，具体实现、门槛数值、验证范围和证据见[实施记录](RAM_HEADROOM_IMPLEMENTATION_20261026.md)。此前[反馈排查与模拟复现](RAM_HEADROOM_FEEDBACK_20261026.md)保留修复前依据。

## 目标与批次

首轮完成估算纠错、统一记账、自动回收及相关诊断，解决可复现的“缓存仍被允许保留、处理却因同一预留线被拒绝”冲突。后续根据代表性任务峰值校准强制检查数值。

输出分辨率、HDR 精度、效果参数、帧序及既有时序语义作为验收合同。用户保存的缓存值继续作为上限，有效额度按任务和当前余量调整。

第一批验证阶段沿用原系统预留，单独确认协调修复；第二批根据 7 类实际负载完成校准，当前数值为 `min(4 GiB, max(2 GiB, 总物理内存/8))`。没有可回收空间且余量仍不足时，保留拒绝和安全退役。

### M1 的边界

- GUI 总流程预检、NR/VSR 初始化、逐帧暂存、HDR 解码及 GPU 编码各自明确检查内容。上层流程估算不能在资源已经创建后又被当作整套待分配需求重复要求。
- 已创建缓冲已体现在 OS 快照中；账本里的已分配统计用于归属与诊断，不再作为待分配字节重复扣除。未来暂存和并存副本仍须覆盖。
- 系统预留、工作区余量与推荐值的职责写明。首轮修正重复/未启用阶段和口径差异，不依据单个样例任意削减未知驱动/模型工作区的保护。

### M3～M6 的边界

- 保留当前安全底线：账本协调不能替代真实物理/提交快照，也不能防止外部程序突发分配；真实分配失败仍需完整回滚。
- 回收确认表示所有者已处理该代请求，不表示申请的字节全部归还系统。缓存仍被活跃引用或分配器保留时，以新快照和所有权状态继续判定。
- 严重压力允许立即停止；正常回收有界等待。失败的资源所有者在确认退出前仍保留，沿用已有 NR/VSR 安全退役约束。
- 当前进程可提交量与系统全局提交余量分开命名；跨进程额度协调不以 GUI 的可提交量代替每个实际分配进程的限制。
- 处理额度在所有缓存插入路径生效；暂停、等待状态也能响应回收，避免处理者等待缓存释放而缓存所有者又在等待处理者的循环。

## 首轮验收矩阵

- [x] 模拟 8/16/32/64/128 GiB，覆盖预留线以上、线边及线下；真实硬件记录其实际容量，不把模拟容量写成多机实测。
- [x] 复现缓存占满场景：有足够可回收数据时回收后通过；被当前帧引用、无法实际释放时正确报告不足。
- [x] 两个处理者同时申请；分配完成后额度更新；阶段切换、初始化失败、取消、子进程异常退出及关闭重试均不遗留待分配额度。
- [x] 暂停及空闲时 GUI、RenderSession 和模型缓存均能响应；代次过期、确认超时、新请求覆盖旧请求均不错误恢复预取。
- [x] 物理可用量高而可提交量低；账本占用下降但 OS 余量未上升；缓存快照未过期但真实余量改变。
- [x] 正常运行、回收、恢复预取及严重压力退役，不出现反复弹错、无限等待、死锁或原生处理的隐式重跑。
- [x] 使用既有小样本覆盖 SDR、HDR 1 倍、2/4 倍超分、光流及 FG 关联路径；重点检查 HDR 未启用 VSR 的估算和实际创建一致。
- [x] 取消后重开、清理缓存、退出及连续任务，保持资源归属与必要的时序 reset，输出分辨率/精度/帧序和效果合同一致。

测试优先覆盖 memory_budget、shared_cache_budget、guidance/render cache、NR/VSR worker、HDR/导出边界及相关文案；仅为明确风险补充集成验证。复用已验证环境与本地素材，模拟压力，不制造真实 OOM。执行前按仓库卫生守则登记单一任务目录、盘空间、峰值预算和保留期限；首轮没有全仓回归或大包构建要求。
