# NVIDIA 消息服务令牌兼容修复与验收 · 2026-11-11

## 本次交付

按维护者最新要求，优先修复“我们自己的工作进程与 NVIDIA 消息服务之间的令牌访问兼容性”。
**已实现产品侧源头兼容处理，并验证它停止本轮已确认的 MessageBus 线程风暴。**
没有用内存限额替代源头修复，没有实施中途续导，也没有修改驱动、服务、注册表或已安装应用。

在同一沙箱、同一最终产品代码及运行库下，关闭兼容处理的 NR 对照，检查点间新增
189,568 个 MessageBus 线程；默认启用后，NR／VSR 五分钟首帧后空闲及后续实际处理的
检查点间新增均为零，两项通过既定私有提交增长门槛。

这是本机已确认触发条件的修复验收。闭源驱动本身每线程约 184 bytes 的保留仍存在，
原用户 32 GiB 机器的完整长视频、批量处理与整机异常不因此提前宣布全部解决。
[根因及旧证据边界](NVMESSAGEBUS_TOKEN_ACL_ROOT_CAUSE_20261111.md)。

## 接入位置与处理规则

新增 `dlss5tool/nvidia_token_compat.py`，由父进程使用**本次创建进程的既有句柄**处理。
顺序固定为：创建子进程 → 子进程等待启动门 → 绑定 kill-on-close Job → 核对并处理令牌 → 放行初始化。
不按进程名／PID 查找其他程序，不在逐帧路径修改权限。

下列入口显式开启 `nvidia_compat=True`，共用一个实现：

- NR `ProcessLive`。
- 传统 `ProcessSuperResolution`。
- 常驻 GPU 视频导出和 GPU 预览。
- 并行视频导出工作进程。

通用 Job 默认不启用该功能，显卡查询等其他用途沿用原行为。
常驻 GPU 和并行入口由同一 Job 构造阶段处理，不依赖修改各 worker 的命令协议。

实际变更仅限**匹配以下已观察形态**的中等完整性受限主令牌：非 AppContainer；DACL 为三条
无特殊／继承标志的标准允许 ACE，分别是登录 SID 的 `TOKEN_ALL_ACCESS`、Owner Rights 的
`READ_CONTROL` 和 Administrators 的 `TOKEN_QUERY`。仅受限标志本身不是触发开关。

变更前核对父／子 TokenId 不同、子进程仍存活、令牌类型为主令牌。满足条件后，
只为 LocalSystem 增加 `READ_CONTROL (0x20000)`，保留原有 ACE 的**字节内容、相互顺序及尾部空间**。
不使用整份 DACL 的默认模板替换，不增加令牌复制／模拟／分配／调整权限，不改变进程 DACL、
TokenDefaultDacl、用户、组或特权。该权利用于读取对象安全描述符，属于真实的对象访问权限调整，
不提升工作进程的执行权限。
[标准权限](https://learn.microsoft.com/en-us/windows/win32/secauthz/standard-access-rights)
／[令牌对象访问权限](https://learn.microsoft.com/en-us/windows/win32/secauthz/access-rights-for-access-token-objects)。

已有 LocalSystem 读取权限／空 DACL 的路径不重写；空 ACL、拒绝 ACE、特殊／继承 ACE、
其他权限形态、AppContainer、不同完整性或共享主令牌均不修改。不将“没有显式 System ACE”
当作一般性的有效权限计算结果。

成功写入后复读并核对完整候选 ACL、父／子令牌状态、父令牌 DACL，且立即关闭临时 token 句柄。
权限保留在该工作进程的令牌对象上，覆盖整个原生会话，随该对象退休；不在 CUDA 初始化后过早撤回。

## 失败与回滚

- 无法读取元数据或不匹配支持形态时不尝试写入，保留原启动／压力保护行为，并记录 `unavailable`／`declined`。
- 对已识别目标，申请写入被拒或写后核对失败时，**拒绝放行 GPU 初始化**；不尝试提权或扩大授权。
- 写后核对失败会恢复原始 DACL 并再读验证；恢复失败同样阻止启动，Job 构造失败清理关闭本次 Job。
  子进程此时仍在启动门后，不会带着部分准备状态初始化 GPU。
- `memory_budget` 的有界事件队列记录兼容结果和原因，不持有异常、帧数据或 token 句柄。
- 紧急回滚可在启动应用前设置进程环境 `DLSS5TOOL_NVIDIA_TOKEN_COMPAT=off`（或 `0`）。
  该开关只影响随后新建工作进程；不写入全局环境／注册表，回退后仍有原压力保护。

### 同代码关闭对照与五分钟窗口

每项只跟踪工作进程的精确 PID＋创建时间。空闲排除前十秒，按前后各五分之一采样的中位数比较，
算法复用 `compare_p0_stability.window_stats`；既定门槛为增长 ≤0.25 MiB／分钟、分窗差绝对值 ≤16 MiB。

| 用例 | 空闲配置／帧数 | MessageBus 检查点新增 | 私有提交分窗差 | MiB／分钟 |
| --- | --- | ---: | ---: | ---: |
| 沙箱 NR，显式关闭兼容处理 | 30 秒／1,024 帧 | **189,568** | +14.766 MiB | **+54.936** |
| 沙箱 NR，启用 | 300 秒／1,024 帧 | **0** | −12.195 MiB | −3.152 |
| 沙箱 VSR，启用 | 300 秒／1,024 帧 | **0** | −5.641 MiB | −1.458 |

关闭对照内部检查点跨度约 40.325 秒，包含空闲后的帧处理；观测总创建数为 192,624，
不能把总数和检查点增量混用。修复后 NR／VSR 检查点跨度约 313.063／303.863 秒；
VSR 总共观察到三个正常启动线程，不能描述为所有 MessageBus 线程都不存在。
两项五分钟窗口均通过增长门槛；运行时间有重叠，数据用于内存与退出观察，不比较吞吐。

六项原生测量的源码／运行库清单前后均不变，均正常退出、无安全停止或监督器兜底，最终无所属进程残留。
本轮没有再跑三十分钟连续处理／整夜挂机；上一轮普通账户三十分钟数据保留原有版本和适用范围。
