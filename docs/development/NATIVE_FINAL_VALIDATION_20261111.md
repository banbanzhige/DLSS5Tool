## 实际 4K 导出、重复任务与取消

使用任务内生成的 1080p30 SDR／PQ HEVC10 素材和 AAC 音轨，调用产品实际 resident 导出所有者，
执行 NVDEC → CUDA VSR → 可选 NR → NVENC → 原音轨复用 → 事务提交。
联合 NR 使用产品 `device_sr_plan.make_plan` 和已核验的 resident HDR 扩展组件；没有替换运行库。
这覆盖真实编解码与进程生命周期，不等同于完整冻结 GUI 的按钮流程。

| 项目 | 结果 |
| --- | --- |
| SDR／PQ 各 96 帧，输出 3840×2160 | 沙箱／普通账户均通过 |
| SDR／PQ 各重复一次 | 逐帧审计哈希及完整输出文件 SHA256 均与首轮一致 |
| SDR／PQ＋NR 各 96 帧 | 正确组件和参数下，沙箱／普通账户均通过 |

| 长 SDR 源处理到第 24 帧触发取消 | 通过，约 0.150 秒完成取消后退休，无最终输出和事务残留 |
| 帧数、尺寸、CFR PTS、单调 DTS | 所有成功输出通过 |
| 原音轨 packet 数／字节 SHA256／PTS SHA256 | 所有成功输出与源一致 |

共保留 16 次 resident 记录：13 次通过，3 次为测试夹具错误，未冒充通过项。
其中 12 次为完成导出，1 次为符合预期的取消；HDR＋NR 第二次夹具修订后已成功，
随后仍按统一正确的产品选路再次复验 SDR／HDR。
普通账户四次有效导出均为 `worker_retirement=normal`；沙箱八次有效完成导出均为
`forced_after_completed_output`，最后均无 worker 残留。取消另行记录，不计入“完成输出后退休”。

### 夹具修正的边界

1. 初始增强参数 `nr_quality.total=0.8` 不符合 device 路径要求的中性合成契约，
   SDR／HDR 被产品正确拒绝。改用 `total=1`，保留初始失败及当时脚本。
2. SDR 夹具误把通用 encoder 的 `host_library` 当成支持共享 GPU 输入的 `device_host`，
   被兼容性检查拒绝。移除该别名，复用产品 device 选路及扩展组件后通过。
3. 初版 direct-close 夹具从错误模块导入 `memory_snapshot`，在 GPU 工作前失败；
   修正导入并保留原脚本和日志。这不是一次有效的原生关闭测量。

没有放宽媒体、哈希、取消或退休断言，也没有把这些夹具修正写成产品缺陷修复。
每个测量版本的脚本均随证据保留；早期清单的脚本哈希应对应归档快照，不能拿最终脚本倒替。

## 沙箱 CUDA VSR 关闭等待

独立 direct-close 探针使用同一现有 CUDA VSR 配对，所属 Job 和 GPU 启动门，处理三帧后记录关闭阶段。

| 环境／诊断变体 | 自然关闭 | 证据 |
| --- | --- | --- |
| 沙箱，已启用令牌修复 | 60 秒超时 | CUDA stream synchronize 返回 0；进入 native destroy，日志停在 NGX shutdown |
| 普通账户，同脚本／配对 | 通过 | 约 3.53 秒含处理及退出，native destroy 和 CUDA context close 均返回 |
| 沙箱，临时为所属 child **进程对象**补 LocalSystem SYNCHRONIZE | 仍 60 秒超时 | 父进程 DACL 不变；仍停于 native destroy；变体只在诊断脚本中 |

两次超时在 Job 回收后的退出码均为 0，但自然关闭判定仍为失败。
普通账户原始 `supervisor_recovery=true` 是因为自然 worker 退出后 Job 内仍有 updater 后代；
它们在 Job 关闭时被回收，不能据这个字段说普通 worker 也卡死了。

由此可确认：线程风暴消失后，沙箱关闭等待仍存在；单独补进程等待权限未解决它。
还不能证明更具体的 NVIDIA 内部等待根因。没有扩大产品进程 DACL、停用 shutdown、
更换 SDK／驱动或按进程名清理。

产品已有的事务顺序也经实际输出验收：先排空编码、完成音轨与容器，再通知 complete；
父进程给正常退出留出两秒，必要时退休所属 Job；确认退休和暂存文件有效后才发布最终输出。
因此建议保留这条有界生命周期，不重复实现，也不把 complete 通知提前当作 native 关闭完成。

当前构建使用的 `tmp/RTX_Video_SDK_v1.1.0/include/nvsdk_ngx.h` 仅声明 `NVSDK_NGX_CUDA_Shutdown()`。
仓库另一个较新 DLSS SDK 头文件出现 Shutdown1，不足以支持给当前 VSR 配对直接替换函数。

## 闭环结论与下一步

- **当前可关闭**：已定位的令牌访问不兼容 → MessageBus 线程风暴 → 快速私有提交增长触发链；
  以既有关闭对照、修复后的半小时 NR／VSR 数据和实际导出为依据。
- **已有保护且本轮通过**：完成／取消／失败后的所属进程回收，音轨与输出事务完整性。
  保留普通账户和沙箱两种验收，尤其保留自然退出与有界退休的不同结果。
- **继续单列调查**：沙箱 CUDA shutdown 等待。先取得具体等待线程栈或拒绝访问对象证据，
  再决定是否需要补丁；本轮 SYNCHRONIZE 变体无效，不进入产品。
- **仍需发布阶段验收**：完整新冻结发行包、原用户长视频和设置、实际 32 GiB 机器、
  小时级／整夜批量任务及其他驱动／显卡。30 分钟通过不能代替这些场景，也不能宣布所有 P0 场景验收完毕。

本轮没有新增产品代码，之前 197 项＋5 子测试、压力恢复和更新器退出证据保持其原有版本／范围，
未无故重跑全量回归。中途续导继续搁置。没有打包、推送、创建 Release 或上传。
