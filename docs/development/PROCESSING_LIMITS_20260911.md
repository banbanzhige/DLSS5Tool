# HDR 光流与大图限制放宽 · 2026-09-11

本次更新源码启动版本及项目内增强组件；没有修改用户设置、原始素材、原生 DLL，未重打包 `dist/`。

## 已开放

- HDR 渲染通过独立 SDR 分析副本计算 RAFT／NVOFA 光流；原 RGBA16F 直接进入原生渲染和 10-bit 导出，未被分析副本替换。支持明确的 PQ、HLG、scRGB 描述；PQ／HLG 的分析色域支持 BT.2020、BT.709。
- 分析副本使用固定曲线，不做逐帧自动曝光；每次转换只处理 128 行 FP32 临时数据。切换色彩描述会重置引导会话。普通 RGBA8 输入保持原路径。
- HDR 光流预览和 PNG／视频分析图导出解除禁用，使用相同分析映射。分析图仍是 SDR。按帧号解码裁切取得相邻帧，而不是按平均帧率猜测位置；长视频靠后位置的首次预览可能较慢，尚未实现索引化快速跳转。
- 静态图片任务跳过光流，不启动光流模型，不再阻止分块；保留视频设置并显示“不适用”原因。维护者深度模式不被静默关闭，其分块限制仍保留。
- 自定义视频输出单边上限从 8192 提高到 16384，继续通过实际编码器试编码验证。原生宿主入口也在完整共享内存分配前检查纹理尺寸。
- 光流分析长边上限从 1280 提高到 2048，超过 1280 为实验档；默认仍为 512，深度上限不变。旧组件可能拒绝新档位，必须使用更新的增强组件，不能仅改基础应用。
- 静态图除 4500 万像素阈值外，单边超过 8192 也启用分块。已有显卡容量快照时，≤6 GiB 使用 1200 万像素阈值和 3000×1500 块；≤8 GiB 使用 2400 万像素阈值和 4000×2000 块。默认块为 6000×3000。这里不在 UI 回调中启动显卡查询；未知容量保留保守的既有像素阈值。
- 大尺寸 HDR 可按估计显存余量使用所选 2／3 帧在途队列；未知或不足时为 1。实际异步能力仍取决于宿主配置。同步 SDR VSR 导出只分配单槽，避免分配无吞吐收益的额外纹理。

## 验证结果

- `.venv/Scripts/python.exe -m unittest discover -q`：422 项，8 项跳过，其余通过。覆盖输入不变、同步／异步指针、HDR 分析相邻帧、导出清理、设置保留、尺寸和资源边界及 UI 行为。
- RTX 4070 SUPER：本地 PQ／HLG 测试片段各 8 帧 RAFT 路径成功；PQ＋NVOFA 8 帧成功且关闭了算法回退。输出复核均为 `yuv420p10le`、BT.2020，PQ／HLG 标签与对应输入一致。
- 更新后的已部署组件：HLG＋RAFT 双槽异步处理成功，8 帧；接受 2048 分析上限，小输入不会被强行放大。
- 独立 2048×256 输入实际运行 RAFT 2048 分析，输出有限且非零；单次光流约 311 ms，Torch 峰值 allocated 568 MiB / reserved 882 MiB。仅为狭长测试图的单次测量，不是 2048 方图的显存或速度保证。
- 新旧增强组件在同一 512 档位输入下的光流输出逐像素一致。
- HDR 光流相邻帧预览与原尺寸 PNG 导出通过。
- 11637×5120 实际图片经应用 `_process_still_image` 入口处理成功。请求保留光流开启，执行时跳过且没有启动引导工作进程；6000×3000 分块，连续两次输出 SHA256 一致。

## 保留的边界

- 单边超过 16384：仍拒绝。现有分块仍占用完整 GPU 纹理，未实现 VSR／DLSS 全流程流式分块。
- 分块视频时序光流：仍拒绝；当前块间 reset 不能代表正确的视频历史。
- 静态 HDR 文件、高级 HDR 元数据透传、隐藏的深度入口：未开放。
- 不保证全部高分辨率素材能成功编码或分配显存。HDR 实测是路径冒烟，不是实拍高光、暗部、闪光、切镜、肤色的完整主观画质验收。
