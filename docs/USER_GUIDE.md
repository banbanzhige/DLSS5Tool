播放条上的「分离」可将预览和播放控件移到独立窗口；关闭该窗口或点击「停靠」即可返回主窗口。分离前后的帧位置、播放状态和对比分界保持同步。

主工作区与右侧参数面板之间的分界支持拖动：拖动时只显示位置预览线，松开后调整面板宽度并保存；按 `Esc` 或切走工作区可取消，不保存未确认的位置。本地和实时模式采用相同的轻量预览方式。这是面板布局分界，不是画面内的原图／增强对比分界。

透明 PNG 等单张图片会保留透明度：预览的棋盘格仅表示透明区域，不会写入导出图片。
透明图片请保存为 PNG、WebP 或 TIFF；JPEG/BMP 不支持此透明输出，会提示更换格式。
这不改变图片序列仍仅接受三通道 RGB 的要求。

预览等待时保留正常原画面，动态等待提示、已等待时间及可用的处理阶段统一显示在底部状态栏，不再覆盖画面。
有结果后逐帧显示；缓冲预览不等于已处理完整视频，整段导出进度仍在下方单独显示。

队列中每项保存加入时的参数，后续调参不会自动改变已排队任务；需要修改时，可选中任务后使用「应用参数」。支持重试、清理已完成、上移 / 下移，以及暂停或取消后继续处理未完成任务；这不等同于单个视频的帧级断点续导。

### 画面参数

本地「画面效果」按「画面调整」「输出合成」「单次 NR 残差细调」「全局残差合成」「区域保护」分组，点击组标题即可展开或收起。默认只展开画面调整，并记住各组的展开状态；收起不会关闭效果或更改参数。「区域保护」集中放置启用勾选框、羽化和保护区域编辑；取消勾选仍保留区域及羽化设置。

两种模式的常用参数统一按「风格、强度、本地色调、本地结构、皮肤蒙版」排列；「本地色调／本地结构」沿用本地参考项目的名称，不表示只在本地媒体模式可用。「输出混合」单独放在输出合成部分，不与实时模式的总增强强度混为一项。

开关与记忆数值在同一行：关闭按 0 处理，但保留数值；重新开启恢复。数值框支持小数和百分比，例如 `0.75` 或 `75%`；常规值统一显示两位小数，手动输入的精细数值不被显示格式强制取整。输入超范围、非数字时就地提示，保留上次有效参数，不自动截断输入。修正前不能导出、加入队列或向已有队列应用参数。

「扩展调节范围」默认关闭，常规范围 0～1.00；本地开启后最高 5.00，实时开启后使用后端上限（当前常用参数为 2.00），不能把本地 5× 直接当成实时能力。悬停滑条或数值框可查看当前可调范围；1.00 是常规强度参考，不是画质百分比。关闭前如果仍有超限或未完成输入，会列出参数并保持开启，不改原值；先手动调回 0～1.00 后再关闭。载入旧配置中已有的合法高值时自动展开范围，保留数值；撤销恢复高值也恢复所需范围。实时常用参数步进仍为后端的 0.05，本地为 0.01；更多显示小数不等于更高运行精度。

参数区不再显示逐项复位、默认值提示或“非默认”计数，已有数值和开关继续保留。顶部右侧「撤销调参」可回到最近一次编辑或复制前的状态。其旁边的紧凑三点按钮中，「恢复本地画面默认参数…」是唯一恢复入口，确认后恢复画面参数和对应开关，可撤销；不更改预览方式、扩展范围、导出、队列或实时设置。输出混合的单项修改仍只更新合成预览，不清除增强计算缓存。

本地调整区「···」中可「从实时增强复制画面参数…」，实时调整区可「从本地媒体复制画面参数…」。先打开实时模式并等待参数加载；效果链须只有一个 NR 步骤。复制前会列出将覆盖的数值和开关，只处理上述五项，实时侧只处理第 1 遍。超出目标模式当前选择的范围会整次拒绝，不自动开启扩展范围、不截断数值。不会复制输出混合、保护、后续遍数、捕获或导出设置，也不会改变已排队任务；两边不自动同步。复制到实时模式只改草稿，不启动或重启增强；复制到本地按原有规则更新预览。

### 图片序列

在「队列 → 添加图片序列」只选择一帧时，程序会补全同目录、同前后缀与扩展名、连续编号且同尺寸的整组图片；同组多选时仅导入选中的连续范围。同目录其他完整序列会列出供勾选。设置原始帧率及「输入图片色彩」后，每组图片作为一个无音轨视频任务处理，可使用增强、超分与插帧。

- **SDR / sRGB**：8 位、三通道 RGB PNG/JPG，默认选项。
- **HDR / PQ 或 HLG / BT.2020**：16 位、三通道 RGB PNG。像素必须已使用对应的 PQ/HLG 编码，RGB 数值按全范围 0～65535 解释。程序使用你选择的色彩类型，不自动猜测或转换嵌入的 ICC 色彩配置。
- 16 位不代表 HDR；不支持将线性数据、其他色域、灰度或带透明通道的图片直接按 HDR 导入。EXR/TIFF HDR 序列尚不支持。
- 保留 HDR 导出需开启「HDR 高精度处理」；关闭后会映射成 SDR。预览始终映射为 SDR，不用于判断 HDR 显示亮度。
- 不会复制或修改原图。导入后移动、替换或修改图片需要重新导入；旧版 SDR 序列记录可继续使用，HDR 序列记录需要支持此功能的新版程序。

## 可选光流

### 基础包与增强组件

**只做普通增强或超分，不需要安装模型。**轻量版不含 Torch、模型架构或权重。需要引导时，下载完整版，或将同一版本的推理附加包解压到 `DLSS5Tool.exe` 所在目录；附加包自身包含 `mods`，不要解压成 `mods/mods`。

```text
DLSS5Tool.exe
_internal/                  # 基础应用运行文件
mods/
  nvngx_dlssnr.dll           # 可选替换运行库
  enhancement/
    guidance_worker.exe
    enhancement.json
    _internal/              # 组件自带推理依赖，不能省略
    models/                 # 组件默认权重（如附带）
  models/                   # 用户覆盖权重
```

完整组件自带推理依赖，用户无需另装 Python、PyTorch 或 CUDA Toolkit；仍需支持的 GPU 和驱动。软件不自动下载模型、安装依赖或执行安装器。兼容 `.pth` 权重可以外置替换，其他架构不能只换文件名使用。组件布局与查找顺序见 [mods 说明](../mods/README.md)。完整版／附加包仅附 RAFT 权重，不附深度权重。

### 启用与失败恢复

NVOFA 不需要光流权重和迭代。初始化失败会提示并尝试 RAFT（需权重）；处理中失败停止，不中途换算法。新用户默认关闭光流；主动开启时默认选用 RAFT-Large。重启记住上次分析模式，已启用的模式通过环境检查后恢复。深度推理本版暂时下线。开发从仓库根目录 `run.bat` 启动。

1. 在「推理模型 → 分析模式」选择仅光流；后端可选 RAFT 或 NVOFA。
2. 等待环境检查。检查期间模式保持关闭，通过后才会启用。
3. 如果失败，查看模式下方的原因，在「设置 → 模型与组件」核对组件路径、权重、设备或精度，修正后重新选择模式。基础增强功能仍可使用。

分析模式与调节参数都会保存；重启后自动检查上次启用的模式，检查通过即恢复，环境缺失或检查失败才关闭并提示原因。首次使用保持关闭，不运行光流检查；上次主动关闭时也保持关闭。完整组件无需另装 Python、PyTorch 或 CUDA Toolkit，不要只复制组件 EXE。

检查通过不代表所有素材都能满足显存要求。自动／GPU 不会静默回退 CPU；如需 CPU，请主动选择并使用兼容设置。

### 新用户默认参数

| 项目 | 默认值 |
| --- | --- |
| 分析模式 | 关闭；用户主动选择光流后才检查并启用 |
| 光流模型、分析长边、迭代 | RAFT-Large、512 px、6 次；NVOFA 备选网格为 1×1 |
| 光流方向、精度 | 当前帧→上一帧、FP32 |
| 光流显示量程 | 5 px/帧；仅影响可视化 |
| GPU 队列与直连 | 光流启用时 6 帧在途；同卡 RAFT 默认自动直连 |

长边会按模型要求对齐，实际输入尺寸可能略有差异。更高尺寸、更多迭代或更大的模型不保证更好的最终画质。已有显式设置不会自动改成此表。详见 [参数说明](../docs/guidance/GUIDANCE_PARAMETERS.md)。

### 查看与导出分析图

「推理模型」播放器提供原图、光流图和对比；底部「对比 ▾」设置滑动分割／左右并排、对象、居中和图例。两侧帧号、缩放及平移同步，等待下一帧时保留当前完整画面。光流颜色表示方向、亮度表示幅度。

页底可导出整个视频 MP4 或当前帧 PNG，使用源尺寸／源帧率，无音轨和界面叠加；PNG 是 8 位可视化，不是原始浮点数据。预览选择不改增强视频的导出内容。导出可取消，失败／取消保留已有目标。

## 性能与兼容性

- 同一张 NVIDIA GPU 上运行 RAFT 时，可自动使用光流 GPU 直连；兼容提交和合并队列均支持。旧组件、CPU、NVOFA 等未支持配置继续走原路径，不需要修改模型。
- 光流引导支持 SDR，以及从 HDR 原帧生成的独立 SDR 分析副本；HDR 渲染和导出仍保留高精度原帧。光流预览／分析图导出使用 SDR 可视化，不是 HDR 成片。
- 静态图片没有帧间运动，会跳过光流并保留视频设置，不再阻止图片分块；分块视频的时序光流仍不支持。
- 光流分析长边可设到 2048，超过 1280 为实验档，需新版增强组件。默认值不变；高档 RAFT 会明显增加显存和耗时，并非原图或导出分辨率限制。
- 单张图片的光流为零，跳转与明显切镜会重置相关历史。
- 各类画面缓存共享预算，默认 8192 MiB。缓存不跨程序重启，也不能加速尚未计算的帧。RAM 读数表示登记的缓存量，不是进程总内存或显存。
- 「预览性能 → 自动预渲染」默认关闭并记住选择。关闭时，导入、跳转或调参只更新当前帧；播放仍按需缓冲，暂停后停止连续预渲染。开启后会在暂停时继续生成后续帧；中途关闭会停止后续任务并保留已有缓存。
- 分段并行最多使用 4 个工作进程，会增加内存占用，不一定更快。资源不足时可减少并发或尝试较小素材。
- 模型推理显存不足时，不会自动降低精度、更换模型或切换 CPU。

## 输出与画质说明

### 原尺寸增强与超分

- **超分关闭**：在原尺寸上执行神经渲染。普通视频「输出分辨率」选项在处理后缩小画面，不会先降低神经渲染输入尺寸。
- **超分 2× / 4×**：先用 RTX Video 放大，再在目标分辨率上执行 DLSS 5，按源尺寸的对应倍率输出。宽、高均按倍率增长，像素数分别变为 4 倍 / 16 倍，显存与内存需求也会增加。
- 开启超分时，播放使用较低成本的代理预览；暂停、逐帧或拖动结束后再生成目标分辨率精确预览。判断细节时请等待精确预览完成。
- 超大静态图片可自动分区处理，保持目标像素尺寸；超过 4500 万像素或单边 8192 时启用，已取得显卡容量信息时也会为 6／8 GiB 显卡提前分块。仍使用完整 GPU 纹理，单边不得超过 16384，显存和运行库也可能限制成功率。
- 自定义视频输出尺寸上限放宽至单边 16384；实际大小须通过编码器试编码验证，并不保证能编码所有尺寸。

### 格式、编码与时序

- **图片**：默认沿用源格式；关闭超分时保持原尺寸。PNG / TIFF 按无损方式写出，JPEG 等格式会重新编码；无损保存不代表增强后的像素与原图一致。
- **视频**：默认 MP4，也可指定 MKV / MOV，或选择「跟随输入」。跟随输入支持 MP4/M4V、MKV、MOV；AVI / WebM 回退为 MP4。
- **画质**：SDR 默认使用 H.264，最终输出任一边超过 4096 时自动使用 HEVC；支持画质档位或自定义码率。「极高质量」仍为有损视频压缩，并非数学无损。
- **时序**：「严格时序（单会话）」维持完整连续的处理历史；「视觉无损（并行分段）」可加速 SDR 视频，但分段边界可能有细微差异。HDR 高精度与超分任务使用严格单会话。
- **声音**：兼容的源音轨优先直通；MP4 / MOV 中不兼容的音轨会回退为 AAC。

### HDR 与实验参数

- HDR 高精度路径适用于带正确 PQ / HLG 标签的视频，以及按上述要求显式选择 PQ/HLG 的 16 位 RGB PNG 序列；单张静态 HDR 图片尚不支持。
- 大尺寸 HDR 的在途队列可在显存余量充足时使用所选 2／3 帧，否则自动使用 1 帧；不改变严格单会话时序。显存估计不是分配保证。
- 高精度导出使用 HEVC Main10、10-bit 4:2:0，并写入 HDR10 / HLG 色彩标签（色域、传递特性、矩阵、范围）。不复制 Dolby Vision、HDR10+ 动态元数据或源文件的 mastering-display / MaxCLL SEI。
- 界面中的 HDR 预览会映射成 SDR，不能作为最终 HDR 亮度的判断依据；关闭高精度处理后，HDR 视频会映射为 SDR 再导出。
- 本地「扩展调节范围（最高 5.00）」默认关闭。开启后相关参数可扩展至 500%，可能产生过饱和、伪影或过度增强；不同运行库也可能在内部限制参数范围。

## 常见问题

**启动失败，或提示缺少 DLL？**

确认压缩包已经完整解压、`_internal` 与 EXE 位于同一目录，并安装 x64 Visual C++ 运行库。不要混用不同版本的程序文件。

**DLSS 初始化失败，或替换运行库后仍不可用？**

先核对显卡代际、DLL 路径和哈希，再通过「更多 → 导出诊断日志…」或底栏「关于 → 导出诊断」生成报告；无需先导入素材。两种模式共用导出，默认保存轻量快照，不启动 GPU 探针；可保存 `.log` 或 `.json`，并包含已打开的实时工作台状态。需要探针排查时，停止实时增强及本地导出／队列，选择「更多 → 深度检测并导出…」并确认。提交问题时附上应用版本、显卡、驱动、复现步骤及诊断报告；虽然报告已隐藏目录路径及已知目标窗口标题，公开前仍请检查自定义文本等隐私信息。

v2 宿主的「DLSS 渲染 GPU」默认按高性能顺序选择第一张可用 NVIDIA D3D12 显卡，不受显示器接在核显还是独显影响。多张 NVIDIA 显卡时可手动指定；切换会重建隔离的 DLSS 会话。所选显卡被禁用或移除时程序会明确报错，不会静默改用核显。旧版兼容宿主不支持手动选卡。

**预览卡顿，或高倍率超分失败？**

可在「预览性能」中降低播放质量，并按可用内存调整缓存预算（首次默认 `8192 MiB`）。高分辨率或 4× 超分任务可先用更小素材 / 2× 验证，并参考界面的资源风险提示；预览缩放本身不改变导出尺寸。

**为什么重启后模型关闭，或选择后仍显示关闭？**

重启会记住上次模式并自动检查，检查期间暂不启用；只有环境缺失或检查失败才回到关闭，调节参数仍保留。查看模式旁的状态、详情或日志，并在「设置 → 模型与组件」修正缺失权重、组件目录、设备或精度后重试，不要只复制组件 EXE。

**开启光流后渲染变慢，增大缓存有用吗？**

每帧模型计算会增加耗时，首遍未计算的帧不会因增大缓存而跳过推理。先确认使用 GPU、实际精度和日志耗时；可在同样参数下比较 RAFT 与 NVOFA 的质量和速度。更改模型尺寸或参数会影响结果，应以连续播放的细节、拖影、闪烁判断，不只看单帧截图。

**4× 超分的 8K 视频如何编码？**

1080p 做 4× 超分会得到 7680×4320。最终输出任一边超过 4096 时，程序自动采用 HEVC/H.265，SDR 仍保持 SDR；较小 SDR 输出继续采用 H.264，HDR 使用 HEVC Main10。导出前会按实际尺寸和参数试编码；GPU 不支持时回退 CPU（8K 可能明显变慢），实际编码器见日志。MP4、MKV 和 MOV 均可承载 HEVC，但播放器也需要支持 HEVC。若仍失败，请降低最终输出尺寸并附上编码错误日志。

**如何更新？**

免安装版启动后会在后台检查正式版更新，也可通过「关于 → 检查更新」手动触发。以下文件更新功能需安装包含 `DLSS5Update.exe` 的新发行包，并且发布者提供当前版本到目标版本的匹配更新附件；已有 2.1.1／2.1.2 等旧发行包仍需先手动升级一次。

- 轻量版匹配轻量更新包；程序同级安装了附加组件的用户匹配完整更新包。更新包只含版本间新增或变化文件，未变化的 Torch/CUDA 和模型不会重复下载。
- 下载前显示版本、安装形态和体积；校验后再次询问是否退出安装。导出、队列或诊断未结束时不会自动退出；稍后再次检查更新即可继续。
- 助手在程序完全退出后备份并替换官方受管文件，失败时尝试回滚。设置、队列和未受管的自定义文件不覆盖；受管文件被修改（例如手改 `_internal` 运行库或官方模型）、缺失或有路径冲突时停止更新，转为手动整包升级。自定义组件目录需要手动核对兼容性。
- 文件暂存在程序旁的 `.dlss5-update`；该目录还保留旧文件备份。下次更新前会明确询问是否永久清理，不会静默删除备份。取消下载留下的暂存也在下次更新时询问清理。同一安装目录只允许一个 GUI 实例，以防与更新冲突。
- 成功后按助手提示手动启动 `DLSS5Tool.exe`。助手中断时请保留更新目录；启动保护会给出 `DLSS5Update.exe --root "安装目录" --recover` 恢复命令，关闭程序和其他助手后执行。回滚不完整时不要自行删除备份。

**浏览器已下载 `.dlssupdate`，如何安装？** 在「关于 → 安装本地更新包」选择下载的文件。来源版本必须等于当前程序版本，轻量版选 `lite`、已安装附加组件的版本选 `full`。程序仍需连接 GitHub API 核对官方 SHA-256，之后会复制到程序旁的暂存目录，检查更新包与已安装文件，再询问是否退出安装。原下载文件不会被移动或删除；不要双击、解压或手动覆盖。如果官方校验信息不可用，请改用对应形态的新版整包。

没有匹配文件更新包时：轻量版可下载轻量整包；完整版引导到发布页选择完整版或同版本轻量版＋附加包。关闭旧版后，将整包完整解压到新目录，再按显卡代际配置运行库；不要只替换 EXE，也不要未经兼容验证混用旧 worker 和新主程序。发布和恢复细节见[文件更新说明](release/FILE_UPDATES.md)。

## 运行库选择与校验

默认自动检测：存在的自定义路径 → 模块目录中的 `nvngx_dlssnr.dll` → 唯一的已识别候选 → `_internal` 自带库。多个候选不猜选；可手动选择或强制使用内置库，无需覆盖 `_internal`。模块目录默认是程序同级的 `mods`，允许修改，界面显示命中路径。RTX 30 系使用社区适配运行库，不代表 NVIDIA 官方支持承诺；不同显卡和驱动组合仍需实机验证。

本地媒体与实时增强已共用上述 NR 文件发现规则，但这不是按显卡代际自动挑选兼容 DLL。实时模式沿用首次打开时的本地模块设置，更改后请重启应用；SR／FG 特性运行库目录在实时「预设」中单独设置。程序不会自动下载或尝试替换 DLL。
